# Store reviews on the landing page

The homepage shows a few reviews and links to `/[locale]/reviews/`, which lists all of
them. Everything is real: no review on this site was written by us.

## Where the data comes from

`lib/data/store-reviews.json` is generated by:

```bash
node scripts/fetch-store-reviews.mjs
```

**Apple** is automatic. The public customer-reviews RSS feed is per-storefront — a review
left in the Ukrainian store is invisible from the US feed — so the script walks 16
storefronts and merges the results. (If it ever returns zero everywhere, check it against a
big app such as `id=310633997` before concluding there are no reviews: a broken parse looks
exactly like an empty catalogue.)

**Google Play** is manual. Play has no public reviews API and its store listing renders
reviews client-side, so the script cannot reach them. Copy them by hand into
`scripts/curated-reviews.json` from Play Console → Monitoring and optimisation → Ratings
and reviews → Reviews, or from the CSV under Download reports.

Only 4- and 5-star reviews are published. Lower ones are real and worth reading, but the
place to read them is the console.

## Translating

A review is quoted, so the rules are stricter than for marketing copy:

- The `text` field is **the original and is never edited**, not even for punctuation.
- Translations live in `translations` keyed by locale, as `{ title, text }`.
- A review needs no entry for its own `lang` — readers who share the language see the
  original.
- The site **always labels a translation as a translation** and offers the original. Never
  present a translation as the words the person wrote.
- Translate faithfully, not favourably. A blunt four-word review stays blunt. Do not add
  enthusiasm, adjectives or exclamation marks the author did not write. Keep emoji and
  emoticons exactly where they are.

Re-running the fetch script preserves existing translations by review id, and **drops them
if the author edited their text** — a stale translation of different words would misquote
someone. The script prints `<-- NEEDS TRANSLATION` for anything unfilled; until it is
filled, the site falls back to the original, which is correct but unlocalised.

## After changing reviews

`lib/data/store-reviews.json` is imported statically, so the site only picks up changes on
the next build. Commit the regenerated file.
